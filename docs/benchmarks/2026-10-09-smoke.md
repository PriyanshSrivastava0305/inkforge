# Smoke test — 2026-10-09

Script: `scripts/smoke_ollama.py <model> <runs>` (stdlib only). Ollama 0.34.0, Windows 11.
Machine: Intel i7-1165G7 (4C/8T), 16 GB RAM, no discrete GPU, so inference ran on the CPU.

## What was tested

1. **Structured output:** BookSpec-lite (logline, genre, tone, POV enum, tense enum, 2–4 themes, 2–4 characters, int target) via Ollama `format: <JSON schema>`, `num_ctx 4096`, temp 0.4. Validated by code.
2. **Prose:** ~200-word opening scene, temp 0.85, top_p 0.92, repeat_penalty 1.08.
3. **Truncation signal:** `num_predict 40` on a 300-word request; expected `done_reason = "length"`.

## Observations

- **1B:** schema-valid but shallow. Characters are named by role ("Lighthouse Keeper", "Marine Biologist", "Local Fishermen"). Fine for testing the pipeline wiring, not for judging quality.
- **8B:** proper names ("Ethan Blackwood", "Ava Moreno"), a logline with a twist, readable atmospheric prose. Usable as the quality baseline.
- **HTTP 500 on first 8B request** right after the 1B run. A direct retry succeeded. Free RAM with the 8B loaded was ~0.8 GB. Likely cause: memory pressure while loading the 8B with the 1B still resident. → The router must unload before switching and report load failures clearly.
- `POST /api/tokenize` → **404** on Ollama 0.34. Use a cached Llama-3 tokenizer or the chars/token fallback.
- Prose output contained non-ASCII dashes that printed as `�` in the console (encoding only). Write UTF-8 explicitly everywhere.

## Projections (8B)

- 2,000-word scene ≈ 2,700 output tokens ÷ 3 tok/s ≈ **15 min**, plus prompt reading (3k cold tokens ≈ 4–5 min; much less with prefix caching) ⇒ ~15–20 min/scene.
- 80k-word novel (≈ 40 scenes): ~10–14 h of drafting, plus critique passes. That's a multi-night batch.
